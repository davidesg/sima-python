# Review of `atsw` 1.6.1 — findings on `drvarma` / `sima`

**Date:** 27 September 2026
**Versions reviewed:** atsw 1.6.1 · fue 0.1.16 · pyfug 2.0.1 · art-tseries 0.2.2 · drtran 0.2.5 · drvarma 0.1.7
**Test environment:** Python 3.12.3, Linux x86_64, clean venv (`pip install atsw`), numpy 2.5.3, scipy 1.18.1, mcp 1.30.0
**Data:** the examples included in the package (`IPC_ES.csv`, `WTI.csv`, 2002-01 to 2019-12, 216 obs.)

---

## 1. Overview

`atsw` is a metapackage with no analysis code of its own: it installs the five components of the suite and the `atsw-mcp` command, which registers the three MCP assistants (`art`, `mtram`, `sima`) in Claude Code or prints the equivalent JSON configuration for other clients.

The installation is clean (`pip check` with no conflicts). The components with a C extension (fue, drvarma) publish wheels for CPython 3.10–3.13 on Linux glibc and musl (x86_64 and aarch64), macOS arm64 and Windows amd64, plus a fallback `py3-none-any` wheel. The three servers start and respond over stdio:

| server | tools | instructions |
|---|---|---|
| `sima` | 15 | ~2.8k characters |
| `mtram` | 21 | ~13.4k characters |
| `art-mcp` | 48 | ~45.8k characters |

drvarma's point estimates agree with `statsmodels` (VAR by OLS) to the third or fourth decimal place, and the C engine and the Python fallback give identical results for VAR. The code is very defensive: it checks finiteness after Box-Cox, discards non-converged fits from the ranking of orders, checks the nesting of likelihoods, verifies the seasonal adjustment before/after and offers `export_fit` to cross-check results.

## 2. Findings in drvarma / sima, by severity

### 2.1 Underestimated standard errors — **SEVERE**

**What happens.** `estimate_py._covariance` (and the `est` of the C engine, which behaves the same way) computes the covariance of the parameters as

```
cov = 2 · f · B⁻¹ / n
```

where `B` is the **BFGS approximation of the Hessian** at the end of the optimisation (`raxopt`), not the real curvature at the optimum. BFGS does not learn the curvature well in flat or badly scaled directions, and the result is standard errors that are too small.

**Evidence (VAR(1), IPC + WTI, λ=0, d=1, deseason=auto, via sima):**

| parameter | estimate | drvarma s.e. (BFGS) | finite-difference Hessian s.e. | OLS s.e. (statsmodels) |
|---|---|---|---|---|
| φ₂₁ (WTI ← IPC₋₁) | −2.652 | **0.0267** | 2.402 | 2.428 |
| φ₁₁ (IPC ← IPC₋₁) | 0.210 | 0.0588 | 0.0719 | 0.0727 |
| φ₁₂ (IPC ← WTI₋₁) | 0.0104 | 0.0023 | 0.0023 | 0.0024 |
| φ₂₂ (WTI ← WTI₋₁) | 0.344 | 0.0636 | 0.0777 | 0.0786 |

`sima` reports φ₂₁ with **t = −99.4** and a significance asterisk, when in fact the coefficient is not significant (t ≈ −1.1). The rest of the standard errors are around 20 % below the correct value.

**Reproduction by simulation.** Bivariate VAR(1) with Φ = [[0.3, 0.1], [0.5, 0.4]], innovation correlation 0.5, n = 400, varying the ratio of standard deviations between series:

| s.d. ratio | ML s.e. / OLS s.e. (φ₁₁, φ₁₂, φ₂₁, φ₂₂) |
|---|---|
| 1 | 0.99 · 0.99 · 0.99 · 0.99 |
| 10 | 0.92 · 1.00 · 0.97 · 0.96 |
| 30 | 0.95 · 0.96 · 0.99 · 0.97 |
| 100 | 0.84 · 1.05 · **0.01** · 0.84 |

The result is identical with the C engine and with `DRVARMA_NO_ENGINE=1`, so the problem is in the shared algorithm and not in the C implementation.

**Downstream impact.** `irf.irf_fevd_bands` generates the Monte Carlo bands of `impulse_response` and `variance_decomposition` from that same `cov`. Replacing only the μ/Φ block with the covariance of the finite-difference Hessian:

| response | point | current 95 % band (BFGS) | corrected 95 % band |
|---|---|---|---|
| WTI ← IPC shock, h=1 | +0.806 | [+0.283, +1.438] | [−0.221, +1.806] |
| WTI ← IPC shock, h=2 | +0.022 | [−0.191, +0.362] | [−0.615, +0.758] |
| IPC ← WTI shock, h=1 | +0.074 | [+0.044, +0.107] | [+0.042, +0.108] |
| IPC ← WTI shock, h=2 | +0.041 | [+0.022, +0.066] | [+0.020, +0.065] |
| FEVD WTI by IPC, h=12 | — | [16.1, 38.1] | [15.8, 38.0] |

The response of WTI to IPC at h=1 **changes from significant to not significant**. The WTI → IPC channel (pass-through) and the FEVD barely change, because they depend mostly on well-estimated parameters and on the contemporaneous Σ.

**Proposed solution.** The solution already exists in the suite: `drtran/estimate.py` computes the Hessian with `_qnewt.fdhess` at the optimum and checks that it is positive definite before inverting it. Its own comment acknowledges that drvarma's BFGS approach "is not the curvature at the optimum". `drvarma/_qnewt.py` already includes `fdhess`. Options, from best to worst:

1. Compute `cov` in drvarma with `fdhess` at the optimum, with the same positive-definiteness check as drtran. If it fails, fall back to BFGS and flag it explicitly.
2. At the very least, add a warning in `confirm_and_estimate` and in the band tools when the covariance comes from BFGS, and do not mark significance asterisks.
3. For pure VAR (q = 0), use the analytical information matrix, which is exact and cheap.

### 2.2 Confusing parameter table in `confirm_and_estimate` — **MEDIUM**

- All parameters are labelled `θ[i]`. This clashes with the Θ notation of the MA part and does not indicate which element of which matrix each index corresponds to (μ, Φₖ[i,j], Θₖ[i,j], qq). An analyst, or an LLM, cannot relate `θ[4] = −2.65` to Φ₁[2,1] without knowing the internal packing order.
- t-ratios with an asterisk are shown for the elements of the covariance (`θ[8] = 1.9035`, t = 914.4). In the concentrated parametrisation, invariant to the scale of qq, those t-ratios have no interpretation.

**Proposal:** label them as `mu[IPC]`, `Phi1[WTI,IPC]`, `Theta1[...]`, etc., and omit inference on the covariance parameters, or separate them into a block of their own without t-ratios.

### 2.3 `load_data` silently accepts a date column — **MEDIUM**

With a `date,IPC,WTI` CSV, which is the format of the package's own example files:

```
Cargado 'dated' (series ORIGINALES): 216 obs × 3 series ['date', 'IPC', 'WTI'] ...
- date: n=216  mean=nan  variance=nan ...
```

`characterize_series` processes `date` as just another variable (λ=0, d=1, seasonal: no, ARMA≈(1,0)). The error only appears when estimating, and with a misleading message:

```
La estimación de VARMA(1,0) falló: the transformed series is not finite for ['date']
(lam=0.0): lam=0 is a log and needs strictly positive data...
```

In addition, the start of the sample is not deduced from the dates: by default it is `(2000, 1)`, even though the data start in 2002-01. If the LLM does not pass `start_year`, the calendar is shifted, and with it the phase of the seasonal adjustment and the dates of the forecast.

**Proposal:** detect non-numeric or date columns, exclude them as series, use them to infer `freq` and `start` when these are not given, and reject any column that is entirely NaN.

### 2.4 Inconsistent convergence semantics — **MEDIUM**

Using the library directly, a VARMA(1,1) without seasonal adjustment (IPC+WTI, λ=0, d=1, with mean) ends with:

- eigenvalues of Θ₁ with modulus **1.00005** (non-invertible MA);
- eigenvalues of Φ₁ with modulus 0.99987 and Φ₁ ≈ Θ₁ (near-common factors, model practically unidentified);
- `termcode = 3` and **`ifault = 0`**.

The `ifault` adequacy check does not detect non-invertibility at the boundary. `sima` discards this fit, but only thanks to `termcode`.

In addition, the meaning of `termcode = 3` is contradicted within the suite:

- `estimate_py.py`: *"a line search that cannot find a lower point (termcode 3) means it is AT the optimum, so it is not a fault"*.
- `mcp_server.py` (sima): *"NO es convergencia: el optimizador se rindió. Las estimaciones no son un máximo"*.

**Proposal:** unify the interpretation. It would also be advisable to add to `ifault` (or to a later check in `Model`) the explicit computation of the moduli of the AR/MA roots with a tolerance, and a near-common-factors warning when Φ and Θ are close.

### 2.5 Methodological questions of v1 — **TO DISCUSS**

These are not programming errors, but design decisions that should be documented or revisited:

- **Common λ and d.** The consensus imposes a single λ (0 if all |λᵢ| < 0.25; otherwise, the median) and `d = max(dᵢ)`. An I(0) series will be overdifferenced, introducing an MA unit root, which is exactly what the code itself tries to avoid by limiting `max_d=1`. `Model` only accepts a scalar λ.
- **Additive seasonal adjustment before the log.** `deseasonalize_raw` subtracts harmonic dummies from the *levels* and then applies Box-Cox. With λ = 0 the coherent choice would be multiplicative seasonality, that is, adjusting after the log. For the IPC the before/after check comes out fine (|ACF(12)| drops from 0.750 to 0.070), so it does no harm here, but it can in series whose seasonal amplitude grows with the level.
- **Seasonal parameters not counted.** The s−1 harmonic coefficients (11 for monthly data) do not enter Hosking's degrees of freedom, k for the information criteria, or the uncertainty of the forecast bands.
- **Cointegration warning (Engle-Granger).** The residual of the static regression is tested with `unit_root_tests`, which uses the standard ADF critical values instead of MacKinnon's for residuals. This makes the warning fire too often. In addition, the result depends on which series is placed as the dependent one, since it is always normalised on the first.

### 2.6 Minor

- **Outdated docstring.** `_engine.py` says that the Python fallback covers *"exact VAR only"* / *"q=0 only"*, but `estimate_py` estimates VARMA with q > 0 without any problem.
- **Gaps in the wheel matrix.** There are no wheels for macOS x86_64 (Intel) or for CPython 3.14. Those users get `py3-none-any` and the pure-Python fallback, which gives correct results but, according to the code itself (`elf_c`), is about 250 times slower in evaluating the likelihood. It would be useful to warn at run time when the fallback is used.
- **`--help` in the servers.** `sima --help`, `mtram --help` and `art-mcp --help` start the stdio server instead of showing the help.
- **Context cost.** With the three servers registered, the instructions add up to ~62k characters (≈15k tokens) permanently present in the client's context, plus 84 tool definitions. Almost all of it belongs to `art-mcp`.

---

## 3. Recommended priorities

1. **drvarma's covariance (§2.1):** it changes substantive conclusions (significance of coefficients and of impulse responses). The solution is already implemented in drtran.
2. **Labels and t-ratios in `confirm_and_estimate` (§2.2):** a quick fix that avoids misreadings, above all when it is an LLM that interprets the output.
3. **`load_data` with date columns (§2.3):** a quick fix. It affects the default flow with the package's own example data.
4. **Unify the convergence semantics and strengthen `ifault` (§2.4).**
5. Document or revisit the methodological decisions of §2.5 for v2.

### 4.2 Standard errors versus OLS (§2.1)

```python
import numpy as np, statsmodels.api as sm
from drvarma import mcp_server as S

S.load_data("x", "both.csv", start_year=2002)
S.characterize_series("x")
S.confirm_and_estimate("x", 1, 0)
mod = S._FITS["x"]; w = mod._w

Y, X = w[1:], sm.add_constant(w[:-1])
for i, nm in enumerate(["IPC", "WTI"]):
    r = sm.OLS(Y[:, i], X).fit()
    print(nm, "OLS coef", r.params.round(4), "se", r.bse.round(4))
print("ML params", mod.params.round(4))
print("ML se    ", mod.std_errors.round(4))
```

### 4.3 Simulation with disparate scales (§2.1)

```python
import numpy as np
from statsmodels.tsa.api import VAR
from drvarma._engine import estimate_w

rng = np.random.default_rng(1)
def sim(s2, n=400):
    Phi = np.array([[0.3, 0.1], [0.5, 0.4]])
    L = np.linalg.cholesky(np.array([[1, 0.5*s2], [0.5*s2, s2*s2]]))
    w = np.zeros((n, 2))
    for t in range(1, n):
        w[t] = Phi @ w[t-1] + L @ rng.standard_normal(2)
    return w

for s2 in [1, 10, 30, 100]:
    w = sim(s2)
    r = estimate_w(w, 1, 0, include_mean=True)
    v = VAR(w).fit(1)
    print(s2, (r["std_errors"][2:6] / v.stderr[1:].T.reshape(-1)).round(2))
# Repeat with DRVARMA_NO_ENGINE=1 for the Python fallback: same result.
```
